.venv/bin/python -B real_data/tclab/assess.py \
  --data real_data/tclab/upstream/data.txt \
  --before-seconds 100 --accept-model-assumptions \

输出目录必须不存在；重跑请换一个新路径。

还没有 Python 环境？

已验证环境：Linux x86_64 / Python 3.12；需要预先安装 uv。以下命令仅适用于尚无 .venv 的情况，不覆盖已有环境。

python3.12 -m venv --without-pip .venv
uv pip install --python .venv/bin/python \
  --require-hashes --only-binary :all: \
  -r requirements-thermal.lock

本案例仅需已有 NumPy/SciPy 环境；其他平台尚未验证。模型固定环境23°C及作者几何/热容量，不因列名相同就适用于另一台设备。

使用之前

它能做什么，
不能证明什么？

为什么输入不为零，参数仍可能估不准？

输入存在只排除了严格零输入这一种障碍。参数相互补偿、噪声、边界、初态和模型结构仍会影响判断。本例300秒窗口的U触下界，局部数值满秩不是置信区间或全局可辨识证明。

我可以直接上传自己设备的 CSV 吗？

本页没有上传功能。分析命令在你的本地运行，接受明确单位的5/7列CSV；只有固定双节点模型、23°C环境、作者几何与热容量等假设适用时才有意义。不同设备应先确定模型，不能仅改表头。

这是实时拟合或自动推荐下一次试验吗？

不是。切换100/300秒只展示已保存的两组结果；浏览器不求解、不拟合、不操作设备。下一步说明是有条件的建议，不是经过验证的最优试验或安全功率配方。

300秒窗口证明这个方法更好吗？

没有。这两个窗口来自同一已看过的记录，并非两个独立案例。新评估300秒后续RMSE约2.169°C；旧目标约1.887°C仍保留。目标不同，不把新入口包装为精度改善或AI优势。

我能反馈什么，帮助项目变得有用？

最有帮助的是你遇到的具体辨识问题、运行失败点，以及哪条诊断没有帮助。可通过仓库Issues交流，但不要提交设备秘密、客户日志或未经授权的数据。当前尚无外部使用者接入收益证据。
