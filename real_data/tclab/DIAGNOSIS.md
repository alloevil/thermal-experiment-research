# 双加热器记录诊断：先查数据是否含有要估计的信息

`diagnose.py`读取TCLab风格CSV并指出输入信息缺口，不重拟合参数、不调用LLM、不连接设备。

## 使用

从仓库根运行，只需要Python标准库：

```sh
python -B real_data/tclab/diagnose.py \
  --data real_data/tclab/upstream/data.txt --before-seconds 100

python -B real_data/tclab/diagnose.py \
  --data real_data/tclab/upstream/data.txt --before-seconds 300 --format json
```

不提供`--before-seconds`则分析全部记录。报告发到stdout，错误发到stderr并退出2；工具本身不写入数据或报告文件，若要保存请显式重定向到新路径。`--before-seconds`是排除端点的`t < cutoff`，以文件时间列为准，不以行号或从当前时刻相对计时。

## 输入契约

接受以下**明确的表头**，可选UTF-8 BOM以及字段前后空格，列顺序必须一致：

```text
Time (sec),Heater 1 (%),Heater 2 (%),Temperature 1 (degC),Temperature 2 (degC)
```

或原始7列形式，再加`Set Point 1 (degC),Set Point 2 (degC)`。设定值不是环境测量，不参与本诊断。温度列为摄氏度、输入为0–100%的控制指令，不能把电压/PWM值或瓦数改表头后冒充百分比。

数据必须至少2行，时间有限且从非负值严格递增，所有数值有限，每行列数相同，温度高于绝对零度。`--before-seconds`截取后仍须至少2行。程序校验完整文件，再用所选前缀计算；前缀以外的数据不参与诊断值，但后段格式损坏也会导致输入校验失败。每条记录必须对应操作者确认过的“先测温、后施加该行输入”时序约定。

## 怎样计算

对区间 `[t_i,t_(i+1))` 使用第i行的输入，温度y_(i+1)是该区间后的观测。最后一行输入没有后续测量覆盖，必须忽略，报告会明确提示末行变化。

每路输出：
- 实际有后续观测覆盖的输入最小/最大值；
- 输入非零区间数与总时长；
- 时间加权输入积分（单位`percent-seconds`，**不是J或W**）；
- 已施加输入的变化次数（只在相邻已观测区间之间计数，不假设文件开始之前为零）；
- 记录末尾的指令及其是否相对最后一个已观测区间发生变化。

## 结论边界

### 严格零输入

对于此处的双节点模型，alpha_i只出现在`alpha_i * Q_i`项。如果所选窗口所有已观测区间Q_i严格为零，该窗口温度不能辨识alpha_i，**即使另一节点的热量经耦合传过来也不能辨识它**。

输出`no_input_information`与对应`alpha1`/`alpha2`，同时指出这是在指定模型中的结构结论。零判断不使用任意epsilon：非常小但非零的指令不会被错误归类为数学上的零；它是否能产生可测影响仍需噪声与设备信息。

### 有输入不等于可辨识

非零输入输出`not_ruled_out_by_zero_input_check`。恒定非零输入仍可能包含动态信息，不能简单说不可辨识；程序只标记`constant_nonzero_input`，提示进一步检查参数灵敏度/激励强度/噪声。

两路已观测输入完全一致时标记`identical_observed_inputs`，作为缺少独立输入变化的提示；它不是两参数一定不可辨识的证明，因为输出数目、模型结构与先验也很重要。不用相关系数阈值凭空生成根因结论。

### 测温、初态与环境

报告实际两通道初始读数及其差值，不把温差自动判为零偏或未平衡。不会将23°C设定值当真实环境温度，也不会通过温度曲线上升自动证明耦合或硬件故障。

## 补测建议是条件性的，不是执行指令

若目标包含一个未激励通道的增益，报告建议：取得该通道具有后续温度观测覆盖的、由操作者批准的独立输入变化，或提供独立增益标定证据。若已有记录最后一行才开启该路，先补充该输入生效后的观测，而不是重复追加同一末行。

在执行前仍须明确输入单位/时间对齐、设备批准的幅值和变化率、温度限制、观测持续时间、其他通道控制、传感器噪声/校准及起始条件。信息未知时没有自动生成的功率表，没有最优试验排序，也没有安全放行字段可以变成approved。

输出固定`engineering_release=not_supported`和`hardware_action=none`。这是一项数据入门诊断，不是完整结构可辨识分析、模型选择或下一试验信息增益规划。

## 示例证据与测试

原始599行样例：`--before-seconds 100`只覆盖至99.027s，此时Q2已观测输入为零；`--before-seconds 300`的已观测区间包含Q2，零输入规则不再排除alpha2。参见[诊断结果](DIAGNOSIS_RESULTS.md)和`diagnosis_examples/`中的实际命令输出。本地核验日志保存在仓库根的`output/tclab-diagnosis/`（忽略目录，不随仓库发布）。

```sh
python -B -S -m unittest discover -s real_data/tclab -p 'test_diagnose.py' -v
```

这些测试不读取参考拟合结果来决定诊断，也不生成模拟观测。原生拟合和留出研究见RESULTS.md；本模块不改变它们的协议、模型或结论。
